# 原生鸿蒙 UI 修改报告

日期：2026-08-16  
项目：My Expenses HarmonyOS / ArkTS 迁移版  
目标：在不改变记账业务能力和数据语义的前提下，将全应用主要界面统一为更符合 HarmonyOS 的原生 ArkUI 交互与视觉体系。

## 1. 修改结论

本轮已完成应用级 UI 统一，覆盖根导航、账户、交易、模板、更多功能、搜索、统计、设置、账户编辑、交易编辑、预算、债务以及类别/付款方式/标签管理等主要页面。

修改遵循以下原则：

- 使用 ArkUI 原生 `Button`、`List`、`Scroll`、`Select`、`Toggle`、`Menu`、`NavDestination` 等组件完成界面与交互。
- 保留原有蓝色品牌识别、黄色账户识别、收入绿色和支出红色，不重新定义产品业务语义。
- 保留原有页面路由、数据加载、保存、删除、筛选、排序和回调逻辑；UI 组件继续调用原有方法。
- 将主要图标按钮触控区域统一到 48 vp 左右，并补充必要的无障碍文本。
- 采用渐进式改造，未进行数据库结构调整，也未因视觉改造重写业务模型。

最新验证结果：

- ArkTS 单元测试：59 项通过，0 失败，0 错误。
- HAP 构建：`BUILD SUCCESSFUL`。
- 模拟器安装：覆盖安装成功。
- 模拟器关键路径：账户、交易、模板、更多、设置、搜索、统计、预算、债务、账户编辑、交易编辑均完成无写入验收。

## 2. 设计决策

### 2.1 视觉角色

- 品牌主色：用于选中态、主按钮、强调操作和焦点状态。
- 账户黄色：继续用于账户头像和账户身份识别，不与普通按钮颜色混用。
- 收入绿色：仅表达正向金额、收入和增加。
- 支出红色：仅表达负向金额、支出和减少。
- 中性背景：页面底色与卡片表面分层，避免使用大量边框制造层级。

### 2.2 页面结构

- 一级导航：四等分底部导航，选中项使用原生胶囊式浅色背景和品牌色图标文字。
- 二级页面：统一返回、标题和右侧操作区，标题优先，操作按钮保持 48 vp 触控区域。
- 内容区：卡片、列表和表单采用统一间距与圆角，减少页面之间的视觉跳变。
- 更多操作：页面导航使用独立 Tab，页面工具和行操作使用就地展开，短单选使用按钮锚定 `Menu`。
- 空状态：统一使用图标、标题、说明和可选主操作按钮，避免各页面自行拼装。

### 2.3 原生组件选择

| 场景 | 实现方式 | 目的 |
| --- | --- | --- |
| 顶部操作 | `Button` + `Image` | 获得原生按压状态、触控语义和无障碍能力 |
| 列表 | `List` / `ListItem` | 保留滚动、复用和手势行为 |
| 页面滚动 | `Scroll` | 表单和设置页适配不同屏幕高度 |
| 选择项 | `Select` | 保留系统选择器行为 |
| 开关 | `ToggleType.Switch` | 使用系统开关反馈和状态语义 |
| 页面工具 | 就地展开面板 | 保持上下文，避免大型底部弹窗 |
| 短选项 | `bindMenu` | 在触发按钮旁使用系统锚定菜单 |
| 页面导航 | `NavDestination` / 现有 `router` | 保留原项目导航结构和返回行为 |

## 3. 设计资源调整

### 3.1 新增语义色

在 `resources/base/element/color.json` 中增加：

- `surfacePrimary`：主要卡片和表单表面。
- `surfaceSecondary`：空状态图标底、次级选中区域。
- `surfaceElevated`：需要强调层级的浮层表面。
- `surfaceBrandSoft`：品牌色浅背景，用于选中胶囊和 AI 入口。
- `surfaceIncomeSoft`、`surfaceExpenseSoft`：收入和支出浅色表面。
- `interactivePressed`、`interactiveDisabled`：按压与禁用状态。
- `dividerSubtle`：弱分割线。
- `iconSecondary`：次级图标颜色。
- `scrimColor`：弹层遮罩。

这些名称表达使用目的，减少页面直接使用硬编码颜色。

### 3.2 新增尺寸令牌

在 `resources/base/element/float.json` 中增加：

- `native_page_padding`
- `native_content_gap`
- `native_card_radius`
- `native_emphasis_radius`
- `native_list_min_height`
- `native_touch_target`
- `native_header_height`
- `native_bottom_bar_height`

令牌用于统一页面边距、卡片圆角、列表高度、触控区域、标题栏和底部栏尺寸。

## 4. 公共组件修改

### 4.1 PageHeader

`PageHeader.ets` 在保留原有公开属性和回调契约的前提下重新实现：

- 返回、帮助、搜索、筛选、图表、语音、模板和更多按钮统一为原生圆形 `Button`。
- 图标视觉尺寸约 22 vp，按钮触控尺寸 48 vp。
- 标题采用 20 fp、粗体、单行省略，避免右侧操作较多时挤压布局。
- 激活筛选或搜索时使用品牌色表达状态。
- 关键按钮增加“返回”“帮助”“搜索”“更多操作”等无障碍文本。
- 原有 `bindMenu`、`onBack`、`onMore` 等行为保持不变。

### 4.2 EmptyState

`EmptyState.ets` 统一全应用空状态：

- 80 vp 中性圆形图标底。
- 统一主标题、次说明和行高。
- 可选原生主按钮，继续调用页面传入的原操作回调。
- 预算、债务、分布图、标签选择和其他空列表共享同一组件。

### 4.3 AccountRow 与 TransactionRow

- 统一卡片表面、圆角、内边距和最小高度。
- 账户金额、交易金额和辅助信息重新建立字号层级。
- 展开、状态等操作提供更完整的点击区域。
- 收入、支出、余额颜色继续使用原业务语义色。
- 点击账户、点击交易、展开详情和状态切换仍调用原回调。

### 4.4 AccountListPage 与 TransactionListPage

- 页面背景改为统一语义背景。
- 汇总区域、月份分组和列表卡片形成清晰层级。
- 空列表统一使用 `EmptyState`。
- 未修改列表数据来源、筛选结果、分组规则和点击事件。

## 5. 页面修改说明

### 5.1 首页与底部导航

`Index.ets` 的主要调整：

- 将四个底部入口抽取为统一构建器，避免重复样式。
- 当前选中项使用浅蓝胶囊底，图标和文字使用品牌蓝。
- “更多”恢复为第四个正式 Tab，与 Android 信息架构对齐。
- “更多”页完整保留 AI、类别、付款方法、标签、资产负债表、预算、债务、设置八个入口。
- 交易页账户筛选项改为水平原生胶囊选择样式。
- 顶部搜索、AI、交易操作按钮统一原生按压与触控反馈。
- 交易汇总、模板卡片、空状态和浮动操作区统一视觉层级。

### 5.2 账户页

- 累计金额作为独立汇总表面展示。
- 账户卡继续显示账户颜色、名称和余额。
- 展开后的起始余额、支出、当前余额以及编辑/标记/不计入/关闭/删除操作保持原逻辑。
- 新建与账户操作浮动按钮保留原入口和动作。

### 5.3 交易页

- 收入、支出、转账继续使用各自语义色。
- 顶栏更多点击后在页内展开 2×3 工具区，提供分组、排序、分布图、历史、导出和筛选。
- 交易浮动操作区的扫描、拆分、转账、收入、支出入口保持原顺序和回调。

### 5.4 模板页

- 模板列表与空状态统一为原生卡片体系。
- 模板的创建、执行和管理行为未改变。行尾操作按钮改为卡片内展开，周期与提前天数使用原生锚定菜单。

### 5.5 搜索页

- 标题栏、搜索按钮和条件入口统一为原生按钮。
- 金额、备注、收款人、分类、状态、日期、账户、付款方式、标签采用横向可滚动的胶囊选项。

- 搜索结果使用交易卡片层级。

- 设置主页按“数据”“界面”“导入/导出”“备份与恢复”“功能”等层级组织。

- 开关的状态读取、持久化键和回调保持不变。

### 5.8 账户编辑与交易编辑

- 表单置于统一强调卡片中，字段行保持原顺序。
- `TextInput`、`Select`、`Toggle`、日期时间、标签、附件和位置入口继续使用原组件及回调。

### 5.9 预算与债务

### 5.10 类别、付款方式和标签管理

- 新建、编辑、删除、确认和返回动作保持原回调。
- 标签选择页补充公共空状态和明确确认按钮。

## 6. 功能不变控制

本轮采用以下方式控制回归风险：

1. 公共组件保留原属性名和回调签名。
2. 页面中的 `loadData`、`save`、`delete`、筛选、排序、统计和 Repository 调用不因视觉改造重写。
3. 新的原生按钮只包裹现有图标或文字，点击后继续调用原方法。
4. 每个就地展开按钮和锚定菜单选项逐项映射到原导航或业务方法。
5. 模拟器验收只进行导航、打开、取消和返回；没有点击保存、删除或会改变数据的开关。
6. 保留当前 `router` 与 `NavPathStack` 混合导航结构，未在 UI 任务中发起全局导航迁移。

## 7. 无障碍与触控改进

- 顶部图标按钮采用约 48 vp 的可点击区域。
- 底部导航每项占据四分之一宽度，避免小图标成为唯一触点。
- 搜索、AI、更多、保存等关键入口增加或保留无障碍文本。
- 文本颜色使用主/次级语义色，避免辅助信息与正文权重相同。
- 长标题使用单行省略，防止右侧按钮被挤出。
- 表单、列表和浮动按钮在当前 1320 × 2856 模拟器视口内均可见且可滚动。

## 9. 已知边界

- 当前 debug 构建未配置签名，因此产物为 unsigned HAP；不影响本地模拟器覆盖安装与 UI 验收。
- 交易位置录入尚未接入系统定位服务；入口会明确提示且不会写入伪造坐标。
- 编译器仍报告项目已有的旧路由、Toast/Dialog API 弃用提示，以及部分数据库调用的异常处理提示。本轮遵守“UI 修改、功能不变”的边界，没有将这些警告与视觉改造混在一起处理。
- 页面继续使用项目现有图标资源和系统媒体资源，未引入第三方 UI 框架、图片包或在线依赖。
- 本轮没有执行真实保存、删除、导入、导出或开关写入；这些行为通过现有测试和回调保留进行控制，避免验收过程改动用户数据。

## 10. 后续建议

建议后续独立开展以下工作，不与本轮 UI 改造混合：

1. 按 HarmonyOS 目标 API 版本逐步迁移已弃用的 `router`、Toast 和 Dialog 调用。
2. 为账户保存、交易保存、设置开关持久化增加专门的 UI 自动化回归，但使用隔离测试数据库。
3. 在深色模式、横屏、小屏和大字体环境下再做一轮自适应验收。
4. 将仍散落在旧页面中的硬编码间距逐步迁移到本轮新增的语义尺寸令牌。
5. 发布前补齐正式签名配置，并执行真机触控与无障碍服务检查。

## 12. 大型底部 Dialog 回退专项

在模拟器发现交易操作 `ActionSheet` 存在文字挤压、分割线堆叠、操作层级不清和底部面板过高的问题后，本轮对主源码中所有 `showActionSheet` 进行了专项回退。

| 原场景 | 新交互 | 功能保留 |
| --- | --- | --- |
| 交易页操作 | 顶栏下方 2×3 就地展开 | 分组、排序、分布、历史、CSV、筛选 |
| 首页更多功能 | 第四个正式 Tab + 可滚动列表 | 8 个导航入口全部保留 |
| 模板操作 | 卡片内展开 | 编辑、生成计划、周期、自动执行、日期、提前天数、删除 |
| 模板周期/提前天数 | 按钮锚定 `bindMenu` | 所有原选项与当前选中标记 |
| 账户标记 | 账户展开行的锚定 `bindMenu` | 标记写入回调 |
| 交易批量标签 | 多选栏按钮锚定 `bindMenu` | 批量写入、成功/失败反馈 |
| 拆分项 | 子项内展开 | 金额、分类、标签多选、删除 |
| 附件来源 | 附件行下方三按钮展开 | 拍照、相册、文件 |
| 账户字段帮助 | 表单顶部可收起说明 | 7 项原帮助内容 |
| 资产负债表选项 | 顶栏更多按钮锚定 `bindMenu` | 隐藏账户、零余额、图表、PDF 导出 |

回退后的约束：

- `entry/src/main/ets` 中（排除备份文件）`showActionSheet` 数量为 0。
- 新增 `InlineExpansionState` 集中提供布尔展开和单项互斥展开逻辑，避免页面各自实现状态切换。
- 展开按钮、工具按钮、破坏性操作保持不小于 48 vp 的触控高度。
- 删除等破坏性操作继续使用专用确认对话框，未因操作布局改造取消安全确认。
