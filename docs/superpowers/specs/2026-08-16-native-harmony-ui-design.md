# 全应用原生 HarmonyOS UI 统一设计

## 目标

在不改变现有业务功能、数据结构、页面参数和用户操作结果的前提下，将应用界面统一为 HarmonyOS 原生 ArkUI 风格。改造覆盖根导航、账户、交易、模板、编辑表单、设置、预算、债务、搜索、统计、历史记录和通用弹层。

## 决策

采用渐进式原生重构：保留现有蓝色主品牌、黄色账户识别色、收入绿色和支出红色；使用 ArkUI 原生布局与交互组件统一页面外壳。不会进行全量导航重写，也不会只做表面换色。

## 功能不变约束

- 不改变 Repository、数据库表结构、金额换算、交易分类、账户余额和统计口径。
- 不改变页面入参、返回值、保存条件、编辑回填、模板应用和拆分交易行为。
- 不改变点击、长按、滑动、多选、筛选、排序及菜单所触发的业务函数。
- 不删除当前可达入口；暂未实现的功能保持原有提示，不伪装成可用功能。
- UI 修改与业务修复分离；发现既有业务缺陷时记录并单独处理。
- 所有可点击控件目标尺寸不小于 48vp，并补足必要的无障碍说明。

## 信息架构

### 根层级

- 使用 `Navigation` 承载应用根容器和二级页面。
- 使用 `Tabs/TabContent` 承载账户、交易、模板三个主要工作区。
- “更多”保持操作入口语义，界面改为原生底部面板或系统操作面板。
- 根页面状态和已选 Tab 继续由现有状态字段维护。

### 二级页面

- 已迁移页面继续使用 `NavDestination`。
- 仍使用 `router` 的页面先统一视觉和返回行为，确认参数与刷新链路后再迁移。
- 不在一次修改中强制混合路由全部切换，避免破坏回退栈。

## 视觉系统

### 色彩

- 主品牌色沿用蓝色，账户识别色沿用黄色。
- 页面背景、一级表面、次级表面、分割线、文字主次级、选中态和禁用态全部通过资源引用。
- 收入、支出、转账继续使用独立语义色，不使用主品牌色替代。
- 为后续深色模式预留资源语义，不在业务页面直接新增十六进制颜色。

### 尺寸与排版

- 页面水平边距统一为 16vp。
- 页面标题、分组标题、正文、辅助文本和金额分别使用统一字号层级。
- 普通卡片圆角统一为 12vp，强调容器为 16vp，胶囊控件为高度的一半。
- 列表行最小高度为 56vp，主要操作控件最小高度为 48vp。
- 除必要的悬浮操作外，减少阴影，使用表面层级和留白建立层次。

## 公共组件

### 页面标题

升级现有 `PageHeader`，统一返回、标题、菜单、搜索、筛选、帮助和主操作按钮的触控区域、图标色与无障碍说明。业务回调保持不变。

### 状态视图

升级 `EmptyState`，统一空数据、筛选无结果和失败重试样式。保留现有标题、副标题和操作回调。

### 列表与卡片

账户行、交易行和设置项遵循同一文字层级、间距、选中态和分割规则。列表容器继续使用 `List/ListItem`，不改变数据源和事件回调。

### 弹层

- 单选和快捷操作优先使用原生菜单或 `ActionSheet`。
- 简单确认使用系统警告对话框。
- 需要多个字段的编辑流程保留 `CustomDialog`，但统一标题、内容间距和底部按钮区。

## 页面设计

### 账户

保留账户筛选、选择和新增功能。标题区、累计行、账户行及悬浮操作统一视觉；账户色仍作为识别信息，而不是大面积背景。

### 交易

保留账户切换、汇总、筛选、排序、详情、多选和新增逻辑。汇总改为原生信息卡片，交易列表增强金额、日期和类别层级，账户切换使用可滚动标签样式。

### 模板

保留模板筛选、创建、点击应用和金额展示。统一标题、模板列表和新增按钮样式。

### 编辑表单

账户编辑、交易编辑和预算编辑采用分组表单：字段标签、输入控件、错误提示和保存操作使用一致的原生样式。现有校验与保存函数不变。

### 管理与选择

分类、标签、付款方式、预算和债务页面统一为原生分组列表；创建、编辑和删除入口保持原有行为。

### 搜索、统计和历史

筛选条件使用原生筛选行或选择控件；结果列表、图表容器、统计摘要和空状态统一表面层级。查询条件及统计计算不变。

### 设置

设置首页和子页面统一使用 `Navigation/NavDestination` 标题、分组列表、开关和选择项。暂未实现的设置项继续明确显示开发中状态。

## 状态与错误处理

- 加载使用原生 `LoadingProgress`，不覆盖可继续操作的旧数据，除非现有页面已经这样设计。
- 保存中禁用重复提交入口，但不改变提交函数。
- 错误信息使用原有业务文案；UI 只统一展示方式。
- 空态、无结果和加载失败必须可区分。

## 验证标准

- ArkTS 单元测试全部通过。
- `assembleHap` 构建通过。
- 模拟器验证三个根 Tab、“更多”、账户编辑、交易新增/编辑、AI、搜索、设置、预算和债务的进入与返回。
- 验证账户选择、模板进入、筛选面板和弹窗可以正常打开关闭。
- 不通过自动化流程新增、删除或修改用户账目；涉及写操作只检查到确认前一步。
- 对改造前后页面保存截图，检查遮挡、溢出、触控尺寸和系统安全区。

## 分批交付

1. 视觉资源、公共标题、空状态和根导航。
2. 账户、交易、模板核心页面。
3. 账户与交易编辑、分类与标签选择。
4. 设置、预算、债务、搜索、分布图和历史记录。
5. 弹层、无障碍、构建、模拟器回归和修改报告。
