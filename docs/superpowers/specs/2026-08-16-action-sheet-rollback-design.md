# 大型 ActionSheet 交互回退设计

日期：2026-08-16

## 目标

移除应用中会在 HarmonyOS 模拟器上渲染为拥挤大底部弹窗的 `showActionSheet` 交互，恢复更接近 Android 原版的工具栏菜单、页面内展开和独立列表体验。回退只改变交互承载方式，不删除入口、不修改业务回调、不改变保存、删除、筛选、排序或导航语义。

## 问题定义

当前系统 `ActionSheet` 在选项较多或文案较长时存在以下问题：

- 选项行被压缩，文字与分割线过密。
- 弹层占据大部分屏幕，打断当前页面上下文。
- 本可直接展开或就近选择的操作被强制放到底部。
- 长帮助文本、动态标签、周期配置等内容不适合使用同一种弹层。

## 交互规则

### 1. 页面级导航入口

使用独立页面或当前底部 Tab 内容，不使用弹窗。

- “更多”恢复为第四个实际 Tab。
- AI、类别、付款方法、标签、资产负债表、预算、债务、设置恢复为页面内列表。
- 每项继续调用现有 `router` 或 `NavPathStack` 回调。

### 2. 当前页面工具操作

使用页面内可折叠工具区。

- 交易页右上角“更多”只负责展开或收起交易工具区。
- 工具区位于交易标题栏和账户切换栏之间。
- 分组和排序显示当前状态并直接切换。
- 分布图、历史记录、导出 CSV、筛选保留原回调。
- 展开区不使用遮罩，不阻止浏览交易列表；再次点击按钮或切换页面时收起。

### 3. 行级上下文操作

使用行内展开，不使用大底部弹窗。

- 模板长按后展开该模板的操作区。
- 操作区包含编辑、生成计划、周期设置、自动执行、下次执行日期、提前执行天数和删除。
- 删除仍进入独立危险确认 Dialog。
- 同一时间只展开一个模板，避免列表过长。

### 4. 短单选项

使用锚定菜单、`Select` 或页面内选项，不使用 ActionSheet。

- 周期、提前执行天数、账户标记、资产负债表选项使用 `bindMenu` 或现有 `Select`。
- 选中态使用 `✓` 或系统选中样式。
- 所有选项继续调用原 `apply...` 或 `toggle...` 方法。

### 5. 动态多选与长列表

使用页面内展开或现有选择页。

- 批量标签在交易多选栏下方展开标签选择区。
- 拆分项标签在该拆分项下方展开，不离开编辑页。
- 大量模板继续使用已有的限高 `List` 对话框；它是带滚动与固定取消区的内容选择器，不使用系统 ActionSheet。

### 6. 帮助与说明

短说明使用 `AlertDialog`，长说明使用可滚动内容页或可滚动自定义 Dialog。

- 账户字段帮助不再把每段说明伪装成可点击操作项。
- 说明文本没有业务回调，不显示操作箭头或列表点击效果。

### 7. 危险操作

删除、关闭等不可逆或高风险动作继续使用明确的确认 Dialog。

- 主按钮为取消。
- 危险按钮使用支出红。
- Dialog 只负责确认，不混放普通导航和设置项。

## 状态与数据流

新增状态只表达 UI 展开状态，例如：

- `transactionToolsExpanded`
- `expandedTemplateId`
- `batchTagPickerExpanded`
- `expandedSplitPartIndex`
- `attachmentSourcesExpanded`

业务数据仍由现有 Repository、设置服务和页面方法处理。展开状态不得写入数据库，也不得改变原回调参数。

## 关闭规则

- 再次点击同一入口时收起。
- 切换底部 Tab、进入二级页面或执行操作后收起。
- 执行失败时保留当前页面，并通过现有 Toast 或错误提示反馈。
- 危险确认取消后返回原展开位置。

## 可访问性与布局

- 所有展开按钮和操作按钮命中区至少 48 vp。
- 展开区使用 `surfacePrimary` 或 `surfaceSecondary`，不使用全屏遮罩。
- 小屏允许自动换行；长列表必须滚动。
- 展开/收起入口提供“展开交易操作”“收起交易操作”等无障碍文本。
- 展开状态使用箭头方向、选中颜色和文本共同表达，不只依赖颜色。

## 功能不变清单

- “更多”8 个入口全部保留。
- 交易分组、排序、分布、历史、导出、筛选全部保留。
- 模板编辑、计划、周期、自动执行、日期、提前天数、删除全部保留。
- 账户选项、账户标记、批量标签全部保留。
- 拆分金额、分类、标签、删除和附件三种来源全部保留。
- 资产负债表选项和 PDF 导出全部保留。
- 删除类操作仍需二次确认。

## 验证要求

1. 源码中不再出现 `showActionSheet`。
2. 全量单元测试保持通过。
3. HAP 构建成功。
4. 模拟器逐项验证“展开—操作—收起—返回”。
5. 验证小屏下按钮换行、长模板列表滚动和底部操作不遮挡。
6. 验证所有旧入口仍可达，且没有因回退新增数据写入。
